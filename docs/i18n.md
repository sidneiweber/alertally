# Languages (i18n)

Alertally is available in **English**, **Portuguese** and **Spanish**, via
[Flask-Babel](https://python-babel.github.io/flask-babel/).

- **Base language:** English. Strings in the code and templates are written in
  English and serve as the keys for the translations.
- **Language selection:** the `lang` cookie (selector in the user menu, in the
  header) and, without it, the browser language. Unsupported languages fall back to
  English.
- **Files:** `translations/<language>/LC_MESSAGES/messages.po` (edit this) and
  `messages.mo` (compiled from the `.po`). The code lives in `utils/i18n.py`.

## Marking strings

Templates:

```jinja
{{ _('Active alerts') }}
{{ _('Source: %(name)s', name=label) }}
{{ ngettext('last %(num)d day', 'last %(num)d days', days) }}
```

Python (routes):

```python
from flask_babel import gettext as _
flash(_("You have successfully closed the alert."))
```

Strings used in JavaScript are rendered by the server into an `I18N` object at the
top of the `<script>` (see `index.html` and `reports.html`).

Careful: in translated strings, a lone `%` breaks formatting. Use `%%`.

Don't translate anything read by machines (JSON responses from the `/gcp`,
`/alertmanager` and `/aws` webhooks) or the content of the alerts.

## Updating translations

After adding or changing strings, run from the project root (it uses the dev image,
so nothing needs to be installed locally):

```sh
pb() { docker compose -f docker-compose.dev.yaml run --rm --no-deps --user "$(id -u):$(id -g)" web pybabel "$@"; }

# 1. extract strings from the code into messages.pot
pb extract -F babel.cfg -k _l -k lazy_gettext -o messages.pot --no-location --sort-output .

# 2. merge new strings into each language's .po
pb update -i messages.pot -d translations

# 3. fill in the empty msgstr entries (and review the ones marked "fuzzy") in the .po files

# 4. compile the .mo files
pb compile -d translations --statistics
```

The `Dockerfile` also compiles the `.mo` files at build time. Even so, keep the `.mo`
files up to date in the repository, because the dev environment mounts the local
folder over the image.

## Adding a language

1. `pb init -i messages.pot -d translations -l <code>` (e.g. `fr`)
2. Translate the new `.po` and compile it.
3. Add the language to `LANGUAGES` and `_PRIMARY` in `utils/i18n.py` (and to
   `_HUMANIZE`, if `humanize` supports that language, for "5 minutes ago").
